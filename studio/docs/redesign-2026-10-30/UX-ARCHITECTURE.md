# Новая UX-архитектура — проект до реализации

Цель: человек со смартфона собирает персональный подарок и может исправить любой выбор без перезапуска. Визуальное направление: белые/тёплые поверхности, graphite272421, burgundy8D283F, deep6E182F, blushF1DBDE; Onest/Unbounded из проекта. Главная /miglik/ и её GSAP-история не меняются. Внедрение только внутри constructor → существующий /studio/ после QA. Выбор визуального макета — следующий обязательный шаг Product Design Ideate.

## Пять этапов

1. **История.** Для пары/друзей/семьи/себя/другое. Это стартовый шаблон, не отдельный товар и не повод сбросить существующий draft. Два героя создаются автоматически только в новом пустом подарке; сохранённый черновик сначала предлагается продолжить. Сразу видна настоящая рамка с дефолтными слоями.
2. **Герои.** Карточки с именами и настоящими miniHTML-превью. Выбор героя, добавить/копия/удалить с undo. Внутри: лицо, волосы, одежда (торс+рукава+брюки+принт), аксессуары (раскрываемые группы назначения). Все49 цветов и существующие спецкостюмы доступны, не показаны разом. Локальный выбор фильтра не теряет героя. Переключение карточек не сбрасывает настройки.
3. **Оформление.** Реальные3 размера ×2 цвета, готовые фоны и компоновка. Рекомендация размера по числу героев, предупреждение при конфликте без удаления данных. Перестановка/сдвиг сохраняют реальный физический масштаб4cm, доступны кнопки выравнивания как альтернатива drag. Размеры и цены из старогоPRICING, не из макета.
4. **Личные детали.** Фото/изображение как существующий фон и свой принт одежды — явно разные действия. Подписи, дата через текст, выбор существующих5 шрифтов и6 цветов. Дополнительные положения/масштабы раскрываются. Отдельный фото-полароид, музыкальный плеер,QR и генерация3D не заявлены: их текущий renderer не поддерживает. Можно передать пожелание менеджеру существующим путём.
5. **Проверка.** Большой честный результат; состав и доплаты; «Изменить» у каждого раздела; CTA «Добавить в корзину» или «Сохранить изменения». В новой рамке не возникает лишний пустой товар. В корзине можно добавить новую рамку, изменить, продублировать и удалить с отменой. Оформление — существующий экспорт/копирование и VK, не фальшивая оплата.

## Экран и состояния

Desktop:55–60% под настоящий renderer слева, настройки40–45% справа. Mobile: верхнее компактное закреплённое превью подарка, доступное увеличение активного героя, снизу контекстная панель одного текущего решения и фиксированный CTA с safe-area. Никаких тяжёлых ScrollTrigger-сцен внутри task editor. Смена шага — короткая GSAP opacity/transform; частые изменения опций почти мгновенные, с reduced-motion. Клавиатурные действия без лишнего ожидания.

Компоненты: ConfiguratorShell, ProductPreview, PreviewZoom, StoryChoice, StepProgress, CharacterList, CharacterEditor, AssetPicker, ColorPicker, FrameOptions, PersonalDetails, ReviewSummary, PriceSummary, CartDrawer, CartItem, UndoNotice, UploadField, ErrorRecovery. Это предлагаемые компоненты, пока не реализованы.

## Интеграция

Сохранить engine.js как источник композиции/цен/экспорта. Разделить новый presentation shell и adapter вместо переписывания всех2688 строк. Product type descriptor содержит шаги, capabilities, validation, renderer, pricing и summary; будущая квартира — отдельный descriptor, без заглушекCAD.

Состояние: прежние people/frame/frameTexts/cart IDs читаются и мигрируются без потери. Новый UI хранит текущий high-level step, activeCharacter и nested section отдельно от конфигурации. Сохранение edit обновляет только соответствующийcartID; cancel не изменяет исходник. Создание нового не затирает незавершённыйdraft без понятного выбора. MediaBlob хранится отдельно от JSON конфигурации; legacy dataURL мигрируются по возможности, при ошибке исходник остаётся доступен. Удаление временныхmedia только после проверки ссылок из всехdraft/cartitems и срокаundo. Приватные фото не отправляются во внешние сервисы для дизайна или тестирования.

## План QA после реализации

22 исходных регрессионных теста + тесты новой навигации/совместимости/независимостиdraft/cart/media. Браузерные задачи: два героя, обе причёски/одежда/аксессуар, размер/цвет/фон, фото, подпись, назад-вперёд, review, cart, edit/duplicate/delete+undo, сохранение послеreload, ошибки загрузки и переполнения хранилища. Размеры320,360,375,390,430,768,1024,1440. Проверка всехассетов игоризонтальногоoverflow. Отдельно keyboard/focus/reduced-motion/клавиатура телефона; физический iPhone только при наличии реального доступа. До этих проверок реализация и улучшения метрик не объявляются готовыми.
